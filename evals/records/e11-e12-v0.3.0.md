## E11 — STE register

Scope: the 20-fixture E8 set, rewritten at `register: ste`, both voices, level
`high` only. The level axis was trimmed on purpose — register rows carry no
`active at` level column, so the axes are orthogonal by construction and the
extra 40 sessions would measure the level, not the register.

| Gate | Result | Verdict |
|------|--------|---------|
| 0 contractions (shipped linter, `ste-contraction`) | **0 hits in 40/40 rewrites** | **PASS** |
| 100% sentences ≤25 words (shipped linter, `ste-long-sentence`) | **0 hits in 40/40** | **PASS** |
| ≥85% pass both judged axes | 65.0% (active/imperative 70.0%, fidelity 90.0%) | **FAIL** |
| Zero fact loss | 2 losses / 40 | **FAIL** |

The deterministic half — the half the linter enforces in production — is
clean at 40/40. Both judged failures are concentrated and diagnosable:

1. **The active/imperative rubric over-reached.** All 12 axis failures are
   declarative sentences in *diagnostic* replies being marked down for not
   being imperatives — "the lockfile was stale", "the last deploy enabled
   debug logging". ASD-STE100 itself permits declaratives in descriptive
   text; the rule is one *instruction* per sentence, not one imperative per
   sentence. The rubric as written judged description against the procedure
   rule. Same failure class as rig2's E9 register rubric (terse-voice
   conflict): the gate measured a rubric, not the register. A rerun needs a
   rubric that separates instruction sentences (imperative required) from
   descriptive ones (active voice required, imperative not).
2. **Two real losses, both small and real.** An "about three weeks"
   approximation flattened to "three weeks", and two causal clauses dropped
   from one terse rewrite. These are exactly what the anti-loss invariant
   names; they are rewrite failures, not judge noise.

## E12 — both-mode prevention

Scope: 40 prompts (the 20 E8 rewrites the plan names, plus the 20 E9
generation prompts rig2 measured real bounces on), run at `mode: hook` and
`mode: both`, convo/high. Bounce = more than one assistant turn in the
transcript.

| Mode | Replies | Bounces | Rate |
|------|---------|---------|------|
| hook | 40/40 | 0 | 0.0% |
| both | 40/40 | 1 | 2.5% |

Gate ("bounce rate at `both` strictly lower than hook-only"): **FAIL — and
structurally unreachable as written.** Hook mode's own SessionStart injection
already prevents every bounce on this set with this model, so the baseline is
zero and nothing can be strictly lower. The one both-mode bounce (`e9-p09`)
is a single register violation against a 0/40 baseline — noise, not signal.

What the data does support: `both`'s prevention is *equivalent* to hook
mode's on a set where prevention is measurable, while the mode's actual
selling points — the contract stated once (A31), survival of the Codex
resume gap, the block visible in the user's own file — are deterministic
properties proven green in `run_p15.py`. The gate needs redefining the same
way rig2 concluded for E9's post-bounce gate: measure prevention where the
baseline is non-zero (a model/prompt set that actually drifts), or gate on
"no worse than hook, with the injector absent", which is what the mode
promises.

## Eval-design findings (carried forward)

- E11's judged axis needs an instruction/description split in the rubric
  before the number means anything.
- E12's strict-inequality gate presumes a drifting baseline; with modern
  models and injection live, the baseline is zero. Redefine before rerun.
- The linter-as-checker pattern (deterministic E11 gates measured by the
  shipped `lint.py --register ste`) worked exactly as intended and is the
  strongest evidence in this recording: production enforcement and eval
  measurement cannot drift apart.
